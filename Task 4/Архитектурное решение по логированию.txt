Список логов с уровнем INFO:

1. Изменение статуса заказа: логируем время, идентификатор покупателя, номер заказа, статус заказа. 
2. Передача заказа на производство: логируем время, идентификатор покупателя, номер заказа, идентификатор оператора.
3. Расчет стоимости заказа: логируем время, номер заказа, стоимость заказа. 
4. Операции с файлами: логируем время, идентификатор файла, время загрузки файла, размер файла.
5. Операции записи/чтения в БД: логируем время, название БД, время запроса, таблица.
6. Операции с очередями: логируем время, название очереди, идентификатор сообщения.

Можно использовать уровни ERROR (как ошибки, на которые нужно обратить внимание) и FATAL (критические ошибки).
Для отладки можно использовать уровень DEBUG.

Мотивация:

Логирование повысит уровень наблюдаемости системы начиная с этапа разработки и тестирования перед релизом. Возможные аномалии QA может заметить при тестировании бизнес-критичных сценариев. При выполнении тест-кейсов сможет передать лог команде разработки с деталями об ошибке, что поможет команде разработки быстрее фиксить баги.

Предлагаемое решение:

Компоненты для логирования: 
- сборщик логов Fluent Bit + Filebeat для доставки файлов в Elasticsearch
- Elasticsearch
- Kibana + Grafana
- Elasticsearch Security + RBAC для безопасности данных

Диаграмма С4: https://disk.yandex.ru/d/Khyz3gF1aQHuGw

Политика безопасности в отношении логов: 

В Fluent Bit будут настроены правила для маскирования для паролей, токенов и других персональных данных (например номера телефонов и т.д.).
Для доступа к логам будет настроена модель RBAC с отдельными наборами разрешений для разработчиков, devops, поддержки и отдела безопасности.
Для всех соединений использовать TLS 1.3.
Для индексов Elasticsearch использовать шифрование, алгоритм AES-256.

Политика хранения в отношении логов:

Под каждую систему (API, CRM, MES) будет отдельный индекс. Хранится логи по времени и объему данных будут:
- 30 дней для online shop API (2Гб/день)
- 3 месяца для CRM API (2Гб/день)
- 3 месяца для MES API (2Гб/день)
- 1 год для ошибок (1Гб/день)

Необходимые мероприятия для превращения системы сбора логов в систему анализа логов:

Алерты необходимо настроить при следующих сценариях:
- резкий рост новых заказов, более 100 в минуту
- увеличение ошибок при оплате, более 50 в минуту
- более 100 запросов в секунду с одного IP адреса
- рост потребления ресурсов инфраструктуры (загружено более 75% CPU, более 80% оперативной памяти, более 90% хранилища занято)

Автоматически блокировать подозрительные IP (предотвращение DDOS атаки).
Вручную необходимо оперативно реагировать на увеличение потребления ресурсов инфраструктуры, рост ошибок и аномалии бизнес-логики.
