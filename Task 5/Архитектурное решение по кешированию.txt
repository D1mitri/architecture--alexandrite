Необходимо реализовать кеширование на уровне приложения - кешировать списки операторов и статусы, кешировать на 30 секунд списки заказов. Настроить кеширование статических данных. Начать стоит с MES и MES API.

Мотивация:
Так как операторы жалуются на низкую скорость работы со страницей, необходимо разобраться с системой MES в первую очередь. Предлагается кешировать страницу на 30 секунд, добавить кеширование фильтров и результат фильтрации. С помощью redis снизить нагрузку на БД и ускорить получение редко меняющихся данных. Кеширование должно дать улучшение производительности MES интерфейса минимум в 3 раза (если сейчас страница загружается за 3 секунды, ожидаемый результат должен составлять не более 1 секунды).

Предлагаемое решение:
Предлагается внедрить серверное кеширование, т.к. оно поможет снизить нагрузку на БД, будет обеспечена консистентность данных между сессиями и централизованное управление инвалидацией.
Применение паттерна Cache-Aside позволит быстро реализовать кеширование и даст возможность линейного масштабирования.
Write-Through замедляет операции обновления и выглядит избыточным, а также нет необходимости в 100% консистентности данных.
Refresh-Ahead может добавить избыточные вычисления. Также сложно прогнозировать, какие данные понадобятся.

Сущности в кеше: данные оператора, справочники, агрегированные данные.

Предлагается выбрать гибридную стратегию по ключу + TTL.
Лучше подходит, потому что можно выполнить точечную инвалидацию по ключу, групповую инвалидацию + TTL для дополнительной защиты. Изменения будут видны немедленно, в большинстве случаем данные будут загружаться из кеша. Для разработки легко добавлять новые ключи.

Стратегия только по TTL может отразится на консистентности данных, когда оператор обновит статус заказа, а у других какое то время будут отображаться старые данные.

Программная стратегия будет сложной для реализации и поддержки.
