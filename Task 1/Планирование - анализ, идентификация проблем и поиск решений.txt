Существующие и потенциальные проблемные места:
1. Жалобы от клиентов на просроченные заказы
2. Жалобы со стороны пользователей API: проблемы с получением заказа.
3. Жалобы от операторов: первая страница MES, система долго прогружается.
4. Недовольство клиентов онлайн-магазина (B2C) растёт.
5. Один инстанс приложения.
6. Один инстанс БД, который работает на запись и на чтение.
7. Релиз и прод окружения деплоят вручную.
8. Один QA инженер тестирует вручную.
9. Увеличение задержек деплоя из-за увеличившегося количества багов уровня High и Highest.
10. 3d File Storage работает с 3 API: Shop API, CRM API, MES API.
11. Отсутствует механизм кеширования.

Инициативы, которые необходимы для устранения нежелательных ситуаций:
1. Проанализировать жалобы клиентов, пользователей со стороны API и операторов.
2. Добавить инстансы для приложений, чтобы повысить отказоустойчивость системы.
3. Добавить инстансы для БД и настроить разделение записи и чтения.
4. Автоматизировать процессы деплоя на релиз и прод окружениях.
5. Расширить штат тестировщиков, разработать план автоматизации тестирования.
6. Добавить кеширование с помощью Redis, можно начать с онлайн-магазина.
7. Проанализировать нагрузку на 3d File Storage.

Инициативы в порядке приоритета:
3. Нагрузка на один инстанс БД влияет на пользовательский опыт, работу систем и данную проблему необходимо решить в ближайшее время.
6. Кеширование снизит нагрузку на БД и ускорит работу системы.
1. Важным этапом является анализ жалоб от пользователей, отчет с результатом должен помочь в поиске узких мест.
2. Необходимо добавить инстансы приложения для повышения отказоустойчивости системы.
5. Увеличение штата тестировщиков должно помочь ускорить процесс тестирования, чтобы начать автоматизировать тестирование для оперативного выявления сбоев и багов.
4. Минимизировать возможные ошибки при ручном деплое и ускорить процесс деплоя.
7. Разделить файловое хранилище и добавить инстансы, чтобы на этапе работы с файлами минимизировать нагрузку на систему.

Пункт №3. Добавить инстансы для БД, реализовать механизм репликации, разделить чтение и запись, тем самым снизив нагрузку на слой БД.
Пункт №6. Добавить кеширование, чтобы повысить скорость работы онлайн-магазина и системы MES.
Пункт №1. Потеря заказов несет как репутационные риски, так и финансовые. Нельзя оставлять без внимания жалобы клиентов и если для анализа недостаточно данных, настроить системы мониторинга, логирования и трассировки, чтобы выявить и устранить проблемы как можно скорее.
